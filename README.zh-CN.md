# longevity-analyst-skill（中文）

这个 skill 把一位会员的抗衰检测数据变成三样交付物：

- 多组学分析报告；
- 数字孪生快照（`twin.json`），下次复测时拿来对比；
- 带证据的干预方案，交营养师审核。

支持的输入包括：

- WGS：FASTQ、CRAM 或 VCF；
- 甲基化：β 值表或 IDAT；
- 肠道宏基因组：FASTQ 或 MetaPhlAn 谱；
- 血浆蛋白组矩阵；
- 化验单：表格、PDF 或照片。

需要的生信流程（nf-core）在本机运行。每次运行前先做 preflight，检查这台机器够不够、估算要跑多久、占多少磁盘，用户同意后才开始跑。

## 0.8.0 新增：多次复测、基因和化验一起看、带标签的临床条目

- **同一位会员的多次检测**：每一行化验保留自己的采样日期。`la.py twin series` 比较相邻两次、首次和最近一次，并检验缓慢趋势。只有超出个人正常波动（已发表的个体内变异，现在有 32 个指标）才说有变化；没有噪声模型的指标只并排展示。
- **同期在做什么**：宿主传入已采纳的方案项和打卡（`la-exposures/1`），变化旁边列为"同期"，不说成原因。
- **基因与化验的一致性**：分成"倾向已表现""倾向未表现""主要受后天影响""都不突出"四类；复测时记录类别的变化，例如倾向开始表现，就列入问医生的单子。
- **胚系基因指纹**：两次检测的基因型对不上时给出身份提示，那一次不参与对比。只复查化验时沿用之前的胚系结果（APOE、基因与化验、用药基因）。
- **用药基因和营养基因**：直接读会员的 VCF，CPIC 推荐照录原文；**监测计划**：指南规则（如 Lp(a) 一生测一次即可）与方案的复测合并。
- **带标签的条目**（`la-label/1`）：按指南标准的诊断性结论（`cn` 或 `ada` 指南集）、用药建议（指南或 CPIC）、个人反应预测（统计模型：下一次实验能不能看出效果）。每条都写明类别和来源，AI 判断单独标出。
- **中国人群参照**：血脂用山东社区成人的分布，其他指标仍用美国 NHANES，并在报告里写明。
- `deliver/la-export.json` 升级为 `la-export/2`；`deliver/cards.json` 供宿主的健康页使用。
- 新的四次检测示例会员 `examples/case-C`（1000 Genomes 真实基因型，化验为合成数据），测试里跑通全链路。

## 器官体检表（v0.5 新增）

报告里有一张器官体检表，覆盖脑、心血管、肝、肾、肺、胰腺与代谢、免疫与血液、肠道、骨骼肌与骨共九个器官。表里的数据有三种来源，分列显示：

- **测量/模型**：跑了器官时钟才有，目前需要 Olink 或 SomaScan 蛋白组；
- **指数/校准模型**：用化验值按已发表公式计算，包括 eGFR（CKD-EPI 2021）及 KDIGO 分期、FIB-4 及分层、TyG、AIP、China-PAR；
- **AI 估计**：没有算法或没有数据时，由估计子代理以本次检索到的 PubMed 文献为锚，给出器官年龄区间和疾病概率区间。置信度只能标"低"或"很低"，并在报告里单独成列、注明不是测量。

## 三条硬规矩

1. **平台闸门**：质谱蛋白组数据不进任何 Olink 或 SomaScan 训练的蛋白时钟，这一版对质谱数据只做质控描述。
2. **授权模式**：默认按商用模式运行，不跑 GrimAge 等商用授权不明的组件。
3. **数字溯源**：报告正文里每个会员相关的数字，都要通过占位符引用 `readouts.json`；`la.py review trace` 会拒收任何来源不明的数字。
