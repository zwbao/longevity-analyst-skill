# longevity-analyst-skill（中文）

这个 skill 把一位会员的抗衰检测数据变成三样交付物：

- 多组学分析报告；
- 数字孪生快照（`twin.json`），下次复测时拿来对比；
- 带证据的干预方案，交营养师审核。

支持的输入包括：

- WGS：FASTQ、CRAM 或 VCF；
- 甲基化：β 值表或 IDAT；
- 肠道宏基因组：FASTQ 或 MetaPhlAn 谱；
- 血浆蛋白组矩阵；
- 化验单：表格、PDF 或照片。

需要的生信流程（nf-core）在本机运行。每次运行前先做 preflight，检查这台机器够不够、估算要跑多久、占多少磁盘，用户同意后才开始跑。

## 器官体检表（v0.5 新增）

报告里有一张器官体检表，覆盖脑、心血管、肝、肾、肺、胰腺与代谢、免疫与血液、肠道、骨骼肌与骨共九个器官。表里的数据有三种来源，分列显示：

- **测量/模型**：跑了器官时钟才有，目前需要 Olink 或 SomaScan 蛋白组；
- **指数/校准模型**：用化验值按已发表公式计算，包括 eGFR（CKD-EPI 2021）及 KDIGO 分期、FIB-4 及分层、TyG、AIP、China-PAR；
- **AI 估计**：没有算法或没有数据时，由估计子代理以本次检索到的 PubMed 文献为锚，给出器官年龄区间和疾病概率区间。置信度只能标"低"或"很低"，并在报告里单独成列、注明不是测量。

## 三条硬规矩

1. **平台闸门**：质谱蛋白组数据不进任何 Olink 或 SomaScan 训练的蛋白时钟，这一版对质谱数据只做质控描述。
2. **授权模式**：默认按商用模式运行，不跑 GrimAge 等商用授权不明的组件。
3. **数字溯源**：报告正文里每个会员相关的数字，都要通过占位符引用 `readouts.json`；`la.py review trace` 会拒收任何来源不明的数字。

用法和安装见 [README.md](README.md)，流程细节见 `skills/longevity-analyst/SKILL.md`。
